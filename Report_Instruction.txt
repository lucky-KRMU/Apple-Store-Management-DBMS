> **Project Theme:** Payroll & Attendance (specific entities/fields may be extended by the student). The five phases are sequential—each deliverable is the mandatory input to the next, the approved Phase 1 schema cannot be changed in later phases, and the final system must run as one connected application.

| Phase | Phase Title | Work to be Completed | Evaluation Focus | Marks |
| --- | --- | --- | --- | --- |
| **Phase 1** | Data Modeling & Schema Design *(Mandatory base for all later phases)* | Identify entities — Employee, Attendance, Leave, Salary, Payroll. Draw the ER diagram with relationships and cardinalities, normalize to at least 3NF, and convert to a final relational schema with PK/FK constraints. This exact schema must be used unchanged in Phases 2–5. | Correctness of ER model, normalization rigor, schema-design suitability for payroll/attendance logic | 20 |
| **Phase 2** | Procedural Implementation *(Requires Phase 1 schema)* | Implement the Phase 1 schema via DDL. Write stored functions/procedures for salary calculation and tax deduction, and triggers to validate attendance/leave entries (e.g., reject overlapping approved leave dates). Insert realistic sample data covering at least 10 employees across 3 months. | Correct DDL implementation, accuracy of procedures/functions, trigger logic and validation coverage | 20 |
| **Phase 3** | Query & Report Development *(Requires Phase 2 data)* | Using the Phase 2 data, write queries to generate: monthly attendance summary, salary slip per employee, and a late-marks report. Add indexes on columns used in these reports and show the query execution plan improvement (before/after) for at least one report. | Query correctness, report accuracy, demonstrable optimization impact | 20 |
| **Phase 4** | Security, Access Control & Testing *(Requires Phase 1–3 schema and queries)* | Implement RBAC distinguishing HR/Admin (full access) from Employee (read-only, own records). Wrap salary/payroll updates in transactions with proper COMMIT/ROLLBACK. Test the complete system with valid, invalid and boundary test cases (e.g., negative salary, duplicate attendance entry, unauthorized access attempt) and document each test result. | Security correctness, transaction safety, test-case coverage and error handling | 20 |
| **Phase 5** | Integration, UI & Final Presentation *(Requires Phases 1–4 complete)* | Build a basic role-based web or CLI interface where HR/Admin can manage employees and generate reports, and Employees can view only their own attendance/salary records, using the exact backend from Phases 1–4. Submit final source code, README, screenshots/output traces, and a short report explaining real-world use cases (e.g., scaling to a larger firm). | Integration quality, UI/role-based access functioning correctly, documentation, originality, final demonstration | 20 |
| **Total** |  |  |  | **100** |
